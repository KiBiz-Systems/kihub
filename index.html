/02 — The KiHub mandate

FileMaker solutions hold years of business logic, but AI tools struggle to find their way around them, and whatever an AI writes still has to be rebuilt by hand in Script Workspace. KiBuild MCP lets your AI find its way around your solution. FM Bridge turns scripts into text you can edit and paste back. KiBiz Systems built both for our own work and shares them free on KiHub. One change,
start to finish.

A client asks: “Add a 1.5% late fee to invoices that are more than 30 days overdue.” Here is how that change goes with both tools. You can also use either tool on its own.

/01 — Find what it touches

Ask before you change anything

Ask your AI which scripts and layouts use the invoice due date. KiBuild looks it up in your export, so you know what the change will touch before you open Script Workspace.

Ask your AI
Which scripts and layouts use Invoices::DueDate?
KiBuild MCP
/02 — Draft the change

Edit the script as text

Copy the steps of the invoice script in FileMaker and paste them into your editor with FM Bridge. Write the new steps yourself, or ask the AI to draft them, and review the result.

In your editor · example
# Late fee after 30 days
If [ Get ( CurrentDate ) - Invoices::DueDate > 30 ]
    Set Field [ Invoices::LateFee ; Invoices::Total * 0.015 ]
End If

/05 — Quick start

Your first answer in four steps.

Set up KiBuild once, then ask about any FileMaker file you export. Add FM Bridge whenever you want to edit scripts as text.

/01 — Install & connect

Install KiBuild

Paste one line into Terminal (PowerShell on Windows). The installer checks the download, then a setup wizard asks which AI tools you use and connects KiBuild to each one.

macOS / Linux
$ curl -fsSL https://raw.githubusercontent.com/KiBiz-Systems/kibuild-mcp/main/install.sh | sh
Windows (PowerShell)
> irm https://raw.githubusercontent.com/KiBiz-Systems/kibuild-mcp/main/install.ps1 | iex
Already installed? Run kibuild-mcp --setup --update
/02 — Export

Export your file

In FileMaker, choose Tools → Save a Copy as XML… and save it into a files/Source folder inside your project folder.

Or as a script step
Save a Copy as XML [
  Window Name: "MySolution";
  Destination: "files/Source/MySolution.xml"
]
Re-export after you change the file

Add FM Bridge

Install the add-on in your editor, then copy script steps in FileMaker and press Cmd+Option+V (Ctrl+Alt+V on Windows) to paste them as text. Press Cmd+Option+B (Ctrl+Alt+B) to copy them back for FileMaker.

Install · macOS
$ curl -LO https://github.com/KiBiz-Systems/FMBridge/releases/latest/download/fm-bridge-mac.vsix
$ code --install-extension fm-bridge-mac.vsix
Install · Windows (PowerShell)
> curl.exe -LO https://github.com/KiBiz-Systems/FMBridge/releases/latest/download/fm-bridge-windows.vsix
> code --install-extension fm-bridge-windows.vsix

Prefer clicking? Download for macOS or Windows, then in your editor open Extensions → ⋯ → Install from VSIX…. Either way, finish with Developer: Reload Window. In Cursor, Windsurf, or Antigravity, replace code with cursor, windsurf, or antigravity-ide.

Works from your export

KiBuild reads the XML export, not your live file. After you change the solution, save a new export and ask the AI to process it again so its answers stay current.

Your files, your AI service

KiBuild and FM Bridge do their processing on your computer. The AI tool you connect sends what it reads to its own AI service, under that service's terms.

Which steps apply to you

Commands that start with / are for Claude Code. In other AI tools, use the terminal commands and plain-English requests shown here.

/07 — Technical reference

Under
the hood.

For developers who want the details. Full documentation is in each project's README: KiBuild MCP ↗ · FM Bridge ↗

KiBuild MCP compared with plain grep

Without KiBuild (Grep / Raw XML)

  • ✕Find where a script is called: grep -r "Send Email" across hundreds of XML files — noisy, slow, misses numeric IDs.
  • ✕Find where a field is used: Manual regex over calculation XML — misses layouts and relationships entirely.
  • ✕Understand a script: Read hundreds of lines of raw XML step-by-step.
  • ✕Trace a relationship: Open the relationship graph XML and parse join predicates manually.
  • ✕Search the whole schema: Grep tokenizes everything — expensive, context-filling, slow.

With KiBuild MCP

  • →find_script_references_in_scripts returns exact call sites with file paths and line numbers.
  • →find_field_references_in_* covers scripts, layouts, calculations, and relationships: every place a field can be used.
  • →find_script returns a clean step list with names resolved.
  • →inspect_relationships returns structured JSON immediately.
  • →search_index searches workspace_map.md — token-efficient, instant.
How KiBuild processes your export
  1. Export. You save a copy of your file as XML into files/Source/. Single-file and split-catalog exports both work.
  2. Explode. explode_xml_export splits it into one file per object under files/Schema/<db>/: scripts (with plain-text copies), tables and fields, layouts, relationships, table occurrences, value lists, custom functions, and more.
  3. Index. generate_schema_map writes workspace_map.md, an index of every table, layout, table occurrence, and script folder, so lookups don't need to read the raw XML.
  4. Ask. Your AI uses the 32 KiBuild tools to look things up and trace references. KiBuild also tells it when a newer export is waiting to be processed.
All 32 KiBuild tools
/01

Schema navigation

Find scripts, layouts, and tables by name. Inspect relationships. Keyword search the workspace_map.md index. Generate or refresh the schema map. The foundational lookup layer.

find_script find_layout find_table inspect_relationships search_index generate_schema_map
/02

Impact analysis

Trace where a script is called, where a field is used, or what references a table occurrence. Covers scripts, layouts, calculations, relationships, value lists, and variables.

find_script_references_in_scripts find_field_references_in_calculations find_variable_references_in_scripts find_layout_references_in_calculations find_to_references find_relationship_predicates
/03

XML & generation

Explode exports, extract steps, resolve IDs, trace dependencies, match revisions. Validate FMXML snippets and WebViewer HTML. Write versioned artifacts to the outbox.

explode_xml_export xml_extract_steps xml_lookup_name xml_trace_dependencies validate_fmxmlsnippet validate_webviewer_html write_outbox_artifact
/04

Specialist skills

Load domain-specific expertise into AI context. Pro and simple scriptwriter modes, script analysis, FM XML serializer, and script debugging. Skills shape how the AI applies the other 31 tools.

load_skill pro_scriptwriter simple_scriptwriter script_analysis fm_xml_serializer script_debug
FM Bridge: what it handles

Without FM Bridge

  • ✕The AI writes a script, then you rebuild it by hand, step by step, through FileMaker's dialogs.
  • ✕Copied script steps can't be read outside FileMaker, by you or by an AI.
  • ✕No find-and-replace across a whole script.
  • ✕No easy way to compare versions or review a change before it goes in.

With FM Bridge

  • →216 FileMaker script steps can be fully edited as text, and it learns new ones from a single copy.
  • →Nothing gets lost: steps it can't show as text still paste back exactly as they were.
  • →Suggestions as you type for script steps, 136 calculation functions, and 94 Get functions.
  • →Runs locally: no server, no account, no tracking.
